# Running V1

V1 is a local research workflow with a public read-only ledger. It has persistent memory between invocations; it does not schedule itself, discover new documents automatically, connect to Schwab, or trade. New evidence is supplied in a checked packet. The existing personal-site Worker hosts exported research without brokerage or Sail credentials.

## Start locally

Python 3.10+; no external packages required.

```sh
python3 portfolio.py init
python3 portfolio.py preview
python3 brokerage.py demo
python3 -m unittest discover -s tests -v
```

These commands are free of API calls. `preview` shows the model request, including the previous reviewed thesis when there is one. `init` validates the packet and creates the private SQLite schema. The synthetic brokerage demo writes no files and has no network path.

For Sail access, use `python3 scripts/setup_key.py` in an interactive terminal. It writes an owner-readable `.env` through a hidden prompt. If the key is already set, keep it. Never paste credentials into source files, public messages, or commits. `python3 scripts/check_connection.py` checks model availability and reported credit without generating a completion.

## Research, then review

Record your own expectation before spending anything:

```sh
python3 portfolio.py research --prediction 'I expect higher equipment spending to weaken the cash-flow picture, with AI-only returns still unresolved.'
```

This is a paid request. The default is `deepseek-ai/DeepSeek-V4-Pro-0813`, Flex, medium reasoning effort, and a maximum of 16,384 output tokens. The request envelope is limited to 40,000 bytes of serialized JSON. Rates are dated and saved with each run; changing a future rate does not reprice old runs. The initial unsuccessful attempts are preserved, not removed from the cost history.

The request asks for a JSON document through ordinary text output. The provider's constrained-schema path produced unusable responses in initial trials; local schema, length, citation, and qualitative-prose checks remain mandatory. A provider-completed response is not automatically a valid draft, and a valid draft is not automatically reviewed. Sail currently documents `json_object` as unsupported for Responses; see its [support matrix](https://docs.sailresearch.com/support).

The command prints a run ID. Use that exact ID to inspect or resume:

```sh
python3 portfolio.py status RUN_ID
python3 portfolio.py resume RUN_ID
```

`status` is local. `resume` retrieves an accepted response instead of starting a new investigation. If submission was uncertain before an ID was received, it reuses the saved request and idempotency key within the allowed window. It refuses uncertain resubmission after 23 hours or after an API-key change, because the provider's idempotency scope is tied to the key. A client timeout does not cancel provider work. Never start another `research` command merely because polling ended.

Completed, incomplete, failed, and cancelled responses are terminal. An invalid or incomplete draft stays private; there is no automatic paid redraft. A valid draft still needs substantive review: existence of a citation ID does not prove its evidence supports a claim. Check the original sources, financial units and periods, management attribution, and what remains uncertain.

```sh
python3 portfolio.py review REVISION_ID --reviewer Blake
```

Use your name only when you actually performed that review. The initial publication may be checked by the builder and is labeled accordingly. Review is a local editorial action, not a trade approval. Concurrent drafts cannot silently supersede a newer reviewed parent; an obsolete branch must be investigated again against current memory.

## Publish a checked snapshot

```sh
python3 portfolio.py export public/portfolio.json
```

This writes an atomic public JSON artifact containing reviewed history, source facts and references, and aggregate research-cost fields. It excludes raw responses, prompts, private predictions, account identifiers, and errors. There is no export until a reviewed thesis exists. Costs cover research runs in this database, including known costs of unsuccessful runs; any unknown run cost makes the aggregate unknown rather than silently zero. Provider-billed cost is not yet reconciled.

To refresh the personal site when both repositories are siblings:

```sh
python3 portfolio.py export ../personal-site/portfolio/snapshot.json
```

Then run the personal site's checks, build, preview, and deployment workflow. Exporting alone does not deploy. Review the JSON diff before committing it. A public page visit reads this precomputed artifact and cannot launch inference, reveal private traces, or place an order.

## Updating the thesis

Prepare a new evidence packet with the same thesis ID. Use explicit source publication dates and the evidence date, rather than today's date for old material. Facts and context items reference source IDs; model claims reference fact or context IDs. See [packet notes](../data/thesis/README.md).

```sh
python3 portfolio.py preview --packet path/to/updated-packet.json
python3 portfolio.py research --packet path/to/updated-packet.json --prediction 'State what you expect the new evidence to change.'
```

The next run includes the previous reviewed thesis and its evidence packet. SQLite retains each revision's original packet and hash. Review and export the resulting version explicitly. This is how memory grows without editing old conclusions or inventing a historical track record.

## Budget and storage

The research ledger permanently holds a conservative $0.20 allowance per logical run against a $2 initial local limit. It counts uncertain and failed submissions too. This is separate from the original `lab.py` $1 allowance. The allowances are not actual charges and are not refunded automatically. Actual list-price estimates use uncached input, cached input, and output counters; cached input is a subset of input.

The research database is `.data/portfolio.sqlite`; the original experiment uses `.data/runs.sqlite`. Back up both privately with `.env` and any needed evidence snapshots. A new database has new budget history, so do not delete or replace a database to work around a spending stop. Neither local allowance covers other applications or spending outside these runners. Raising limits should be an explicit decision after inspecting usage.

Prices and API capabilities change. Check the [model catalog](https://docs.sailresearch.com/models), [pricing](https://docs.sailresearch.com/pricing), and [completion-window contract](https://docs.sailresearch.com/completion-windows) before changing model, transport, or limits. The September 12 DeepSeek Pro Flex rates per million tokens are $0.66 input, $0.022 cached input, and $1.98 output. Flex requires background execution and can wait longer for capacity. The legacy DeepSeek Flash extraction now uses foreground ASAP; its September 7 result remains recorded as originally observed.

## Schwab next

The [private credential setup](SCHWAB-SETUP.md) is ready: `python3 scripts/setup_schwab.py`. It saves the Accounts and Trading app credentials through hidden prompts without making any API requests. OAuth and the account adapter remain pending verification of the current portal documentation.

`brokerage.py` is an offline synthetic accounting exercise. It reconciles executed fills rather than requested order quantities, separates external funding from P&L, and detects mismatches. It does not implement settlement, dividends, corporate actions, tax lots, FX, or Schwab's response schema.

Before adding the real adapter, inspect the owner's approved Individual Trader API product and account-accessible OAuth documentation. Confirm permitted fields and renewal behavior. Start with read-only observations and keep all account data private; separately resolve display permissions before publishing account-derived metrics. No brokerage key is needed for the current V1.

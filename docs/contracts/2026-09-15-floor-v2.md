# Floor contract v2: events, checkpoint fields and tool fields for the leap

*The shared agreement between the runtime (`ltcm/`), the order gateway (`gateway/`) and the
site (`personal-site/capital/`). Every workstream implements its side of this file and nothing
else crosses the boundary. Money is a decimal string; times are UTC ISO-8601 with milliseconds;
ids obey the site's `eventId` rule (no spaces, no `#`).*

## 1. New event kinds

All on existing stream families, so `kind.split('.')[0]` still equals the stream family.
Register in `ltcm/events.py` `KINDS` (visibility as given), the README kind table, and the
site's `EVENT_KINDS` (label, tone). Payloads are free-form on the site unless listed in §1.1.

| Kind | Stream | Visibility | Payload (all keys present unless marked optional) |
|---|---|---|---|
| `desk.watch` | `desk:<id>` | public | `trigger` (string, the reason id, e.g. `price_move`, `fill`, `resolution`, `new_market`, `headline`), `detail` (≤300 chars), `decision` (`wake` \| `ignore`), `reason` (≤500 chars, the watch model's one line), `cost_usd`, `session_id` (optional; set when `wake` started a session) |
| `desk.forecast` | `desk:<id>` | public | `session_id`, `market` (ticker/symbol ≤80), `venue`, `probability` (decimal string 0..1), `market_price` (decimal string 0..1 or null), `side` (`yes` \| `no` \| null), `resolves_at` (ISO or null), `reasoning` (≤600 chars) |
| `desk.exit_plan` | `desk:<id>` | public | `intent_id`, `instrument` ({symbol, asset_class, venue}), `target_price` (or null), `stop_price` (or null), `time_stop_at` (ISO or null), `venue_native` (bool: the venue holds the bracket), `order_ids` (list of strings, may be empty) |
| `desk.code_run` | `desk:<id>` | public | `session_id`, `code_sha256`, `language` (`python`), `stdout` (≤4000 chars), `exit_code` (int), `seconds` (decimal string), `sandbox` (box id short or null). *Wave 2.* |
| `lab.calibration` | `lab` | public | `scope` (`desk` \| `family` \| `floor`), `desk_id` (or null), `family` (or null), `generation` (int or null), `n` (int), `brier` (decimal string), `reliability` (list of {`bin`, `forecast_mean`, `outcome_rate`, `n`}), `as_of`, `since` |
| `lab.experiment` | `lab` | public | `experiment_id` (`exp-<sha12>`), `hypothesis` (≤600), `family`, `parent_id`, `change` (object, see §3), `variant_desk_id` (or null until spawned), `status` (`proposed` \| `running` \| `adopted` \| `rejected` \| `withdrawn`), `proposed_at`, `evaluate_after` (ISO) |
| `lab.verdict` | `lab` | public | `experiment_id`, `status` (`adopted` \| `rejected`), `evidence` (object: the gate evidence of variant and parent), `reason` (≤600), `as_of` |

Existing kinds gain optional fields (additive, never renamed):
- `broker.order`: `purpose` (`entry` \| `exit`), `exit_reason` (`target` \| `stop` \| `time_stop` \| `desk`), `exit_of` (intent id) when `purpose` is `exit`.
- `lab.result` `metrics`: `by_generation` (list of {`generation`, `desks`, `decisions`, `cost_usd`, `pnl_usd`, `cost_adjusted_excess_pct`, `brier` (or null), `pnl_per_inference_usd`}).

### 1.1 Fixed shapes the site validates (`KIND_PAYLOADS`)
`desk.forecast` (exact keys above; `probability` and `market_price` must be money-shaped strings in 0..1), `desk.exit_plan` (exact keys), `lab.calibration` (exact keys). Everything else stays free-form.

## 2. Checkpoint additions (all optional, so old floors still validate)

`desks[]` gains:
- `positions`: list (≤50) of `{instrument: {symbol, asset_class, venue}, side (long|short|yes|no), quantity, entry_price, mark_price, market_value, unrealized_pnl (signed), opened_at, thesis (≤240), target_price (or null), stop_price (or null), time_stop_at (or null), exit_orders: [{id, kind (target|stop|time_stop), price}] (≤8)}`. Shadow desks publish shadow positions with the desk's `mode` already saying so.
- `mutation`: `{model_profile, reasoning_effort, session_shift_minutes (int), memory_limit (int), persona_trait (≤200), model_changed (bool)}` for bred desks; absent for founders.
- `calibration`: `{n (int), brier (money or null), since (ISO)}`.
- `live_session`: `{session_id, trigger, started_at}` while a session is running, else absent.

Top level gains:
- `lab`: `{experiments: [≤12 of the `lab.experiment` payload shape plus `verdict_reason` (optional)], curve: [≤40 of `by_generation` rows], calibration: {n, brier (or null)}}`.
- `watch`: `{triggers_today (int), wakes_today (int), last_trigger_at (ISO or null), cost_today_usd}`.

## 3. Experiment change spec (the lab's bounded vocabulary)

`change` is an object with any of: `model.profile` (a priced profile), `model.reasoning_effort` (`low|medium|high`), `cadence.sessions` (list of HH:MM, 1..8), `memory_limit` (20..120), `tools_add` (subset of the venue's tool allowlist), `instruments.allow_add` (symbols or series on the same venue), `limits` (any of `max_position_pct`, `max_order_notional_pct`, `max_daily_loss_pct`, `max_orders_per_day`, each within the hard bounds in `ltcm/config.json` `lab.hard_limits`), `playbook_note` (≤1500 chars appended to the child's playbook under "House view"). Nothing outside this vocabulary is accepted; the lab's proposal is validated before it is spawned.

## 4. Tool and intent fields

`propose_order` gains optional `target_price`, `stop_price`, `holding_period_hours` (int 1..720). `OrderIntent` gains optional `target_price`, `stop_price`, `time_stop_at` (derived: created_at + holding period). The risk engine validates that a stop is on the losing side of the entry and a target on the winning side; a proposal that names neither is still accepted (the desk's playbook may forbid it).

New tools: `record_forecast(market, probability, market_price, side, resolves_at, reasoning)` for event desks; `memo_read(desk_id, limit)` for all desks (read-only); `run_code(code, purpose)` for sandboxed desks (wave 2).

## 5. Gateway additions

- `GET /v1/kalshi/ws-auth` returns `{headers: {KALSHI-ACCESS-KEY, KALSHI-ACCESS-TIMESTAMP, KALSHI-ACCESS-SIGNATURE}, path: "/trade-api/ws/v2", expires_in: 30}` for the WebSocket handshake; the signature is over `timestamp + "GET" + path`.
- `GET /v1/coinbase/ws-jwt` returns `{jwt, expires_in: 120}` signed for the user channel (no `uri` claim).
- `POST /v1/kalshi/account/api_usage_level/upgrade` is allowed through (a write that is not an order; not counted against order caps).
- Order bodies may carry Coinbase `attached_order_configuration`; caps count the parent order's notional once.

## 6. Egress additions for the floor box
`advanced-trade-ws.coinbase.com`, `advanced-trade-ws-user.coinbase.com`, `api.elections.kalshi.com` (WebSocket path). Sandboxes (wave 2) get a data-only allowlist and never the gateway host.

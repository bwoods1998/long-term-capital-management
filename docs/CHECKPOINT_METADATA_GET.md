# Checkpoint metadata GETs

The current [Sailbox HTTP API](https://docs.sailresearch.com/sailboxes-http-api) defines `GET /sailbox-checkpoints` and `GET /sailbox-checkpoints/{checkpoint_id}`. `SailboxClient.checkpoint_info` reads one checkpoint and checks its requested ID. `list_checkpoints` reads bounded native pages, preserving their fields and explicit continuation. Both optionally bind every returned row to the exact original source Sailbox, app and checkpoint name. Name alone is not original-operation or source identity proof.

`list_checkpoints(limit=100, offset=0, max_pages=10)` treats `limit` as the native page size, from 1 through 100. It requires the response's exact echoed `limit`/`offset` and boolean `has_more`, advances by the actual row count, and refuses duplicate identities, empty continuing pages, malformed rows or any returned row that fails an exact filter. The local page bound is 1 through 50. A page-bound stop returns `has_more: true` and `next_offset`; it does not claim a complete inventory. Native offsets are bounded at 100000. Listing is not an atomic snapshot: concurrent inventory changes may cause a refusal or an incomplete view. Each native checkpoint JSON response is bounded to 1 MB, with an extra-byte check, declared-length checks and sanitized read errors.

The response's future fields and status strings are preserved. A checkpoint's generation counts saved states, including sleep/pause, and metadata is not a clean-data, current-evaluation, cost or original POST receipt. The list covers checkpoints currently eligible to start from; expiration/deletion removes entries. Even an empty successful page does not settle an earlier uncertain POST or release its liability.

Native errors, including 404, propagate with their status. No fallback changes 404 into an empty list or substitutes a locally recorded ID; no POST, restore, wake, download or automatic retry occurs. The retained actual filtered route's 404 therefore leaves support for that request/account unknown. The legacy `checkpoints(sailbox, recorded=...)` keeps its existing single live-box GET and record-join result for existing callers. Use the separate new methods for native inventory reads.

This source change and its tests use fabricated HTTP responses only. They establish request shapes, bounds and refusal behavior; they do not demonstrate that a native request succeeds or that the original checkpoint operation completed. An operator recovering an uncertain operation must retain its original body/key, verify actual source/app/name/generation/time against the original intent, and preserve uncertainty when native evidence is unavailable. These GET readers do not perform adoption, original-key POST recovery or resource creation.

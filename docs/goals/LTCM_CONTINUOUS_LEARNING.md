# Continuous learning and profitable options production

Owner direction accepted September 30, 2026 UTC (September 29 Pacific). This continues the existing
options run and its accounting baseline; it does not restart the clock. It supersedes earlier work
priorities where they conflict, while retaining funded limits, the money grant, and honest evidence.

The objective is to build, deploy, and operate a continuously learning, recursively improving swarm
of options-trading agents whose real brokerage profits exceed every project input cost. Work spans
game design, the research environment, the harness, data, execution, and feedback. The September 30
market open is the first deployment/evidence milestone, not the completion criterion.

The owner authorizes parallel implementation, routine engineering decisions, testing, deployment,
observation, revision, and qualified real trading. Existing brokerage capital may be lost in full.
There is no authorization for new deposits, borrowing beyond that capital, or unfunded service
spending. Keep the current model stack; Sonnet-to-Sol migration and migration benchmarks are out of
scope. Existing paid resources are to be used productively, with exact additional funding needs
reported before they become unavoidable.

## Required work

1. Repair real-instance restoration, retirement, negative-evidence research allocation, retirement
   summaries, parameter overrides, and ungrounded model audits. Reuse applicable pending work and
   verify deployed behavior, restart recovery, reconciliation, state, order construction, and fast
   experiment preflight.
2. Organize research around economic mechanisms, input availability, expected horizons, execution
   costs, comparisons, and falsification. Use staged experiments, durable lessons, prompt retirement,
   event-driven waits, and compute allocation by information value and credible evidence. Evaluate
   whether current rules reward irrelevant behavior or exclude useful strategies.
3. Test the evaluator against absent/planted signals, leakage, invalid fills, parameter ablations,
   and state defects. Ground reviews in the execution contract and reproducible evidence. Preserve
   lineages, multiple-testing controls, sealed data, and frozen versions. Observations that influence
   a revision are training evidence for that revision.
4. Expose useful existing inputs, including volume where available, with causal history and clear
   coverage/quality. Explore distinct economically feasible options mechanisms. Extend historical
   data without blocking independent work on usable data; acquire new inputs only for justified,
   funded hypotheses.
5. Deploy persistent live practice with immutable versions, meaningful observation periods, decision
   and execution receipts, honest feedback, and untouched subsequent evaluation. Keep calibration
   separate from strategy evidence. Promote qualified strategies, accounting for shared exposures,
   correlation, liquidity, and available capital.
6. Run a persistent harness-improvement loop: measure a bottleneck, propose an isolated change,
   implement, run fixed benchmarks and regressions, compare quality/cost, canary, retain or revert.
   Demonstrate repeated independently evaluated improvements. The optimizer cannot unilaterally
   change sealed evidence, the profit objective, funded limits, or capital permissions.
7. Reconcile brokerage activity and every input cost. Report trading P&L, ongoing cost, and cumulative
   Net separately. Deposits are not profit; historical costs remain. Prevent silent interruption from
   funding expiration or operational dependencies.

## Completion evidence

All of the following are required; missing or indirect evidence means the goal remains active:

| Requirement | Authoritative evidence |
|---|---|
| Continuous operation and recovery | Deployed release and process status, restart/failure exercises, post-recovery ledger and health |
| Complete research-to-market loop | Versioned research, independent evaluation, qualified real executions, feedback receipts, fresh evaluation boundaries |
| Repeated harness self-improvement | At least two retained changes with predeclared benchmark comparisons, independent checks, canary observations and rollback records |
| Qualified forward performance | Existing agreed independent forward-promotion requirements satisfied by immutable qualified versions |
| Positive cumulative project Net | Reconciled realized options P&L after fees exceeding all input costs since the existing reset; open positions/liabilities reconciled so unresolved losses cannot manufacture profitability |

No forced trades, hidden costs, contaminated evaluation, cherry-picked reporting, weakened success
criteria, or retroactive scoring changes can establish completion. Neither a repaired harness,
passing backtests, paper profits, nor one completed engineering checklist ends the work.

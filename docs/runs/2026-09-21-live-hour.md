## Accounting and recursive-development fixes

Paper reconciliation may no longer absorb missing owned units into a negative baseline. On
restart, legacy negative baselines identify the agents that held the affected instrument when
the adjustment was written. The attribution defect remains visible even if a later baseline is
rewritten. It blocks promotion before paying for another audit and is rechecked after an audit;
the contaminated record cannot earn performance or niche-floor credits. Other agents retain
their earned path. This does **not** reconstruct missing executions or repair historical marks.
The unresolved Haghani record needs provenance-backed repair and contaminated-evidence exclusion,
or a separately identified fresh candidate. Existing history is retained, not rewritten.

Researchers and the production auditor now see the actual order outcomes attributed through
House allocation shares. An eventual “order not found” no longer hides the original insufficient
position error. Health and reconciliation receipts distinguish aggregate agreement from agent
attribution. Tests reproduce the legacy green-aggregate/phantom-position case, prevent future
masking, verify restart persistence, and prevent an audit race from granting capital.

The architect proposed a realized-volatility tool in PR 46, but its CI failed because a sandbox
test assumed a fixed count of parent uploads. Adding any tool shifted that count and made an old
parent execution look like execution by an unsealed child. The test now measures the actual
fork boundary and still requires no child execution, no retained child, and termination on a
sealing failure. This removes a real obstacle to autonomous tool additions.
